# 手机端任务核对页：A 同学的第一个开发任务

日期：2026-09-25。当前交互方向已更新为 [录音便签首页与详情](录音便签首页-交互设计.md)。本文保留单项任务核对流程作为便签“加入日程”后的子流程。已有蓝色本地界面代码尚未浏览器验收，用户正在选择新的纸质便签 UI；前端先适配屏幕，手机系统不再是选稿前置条件。

## 1. 手机端与赛事要求

本次在 [Anker 赛事官网](https://career.anker.com.cn/hackathon/) 打开“智能录音 → 赛道详情”，核实任务目标包含：应用在手机端运行，并结合 soundcore Work 3200 的录音、重点标记、状态信息等能力，形成软硬件协同体验。

因此当前界面可以聚焦手机竖屏，不需要另做桌面产品。官网这段说明没有指定 Android 或 iOS，也没有明确要求双平台、应用商店上架或纯原生实现；不能据此认定一个普通网页已满足最终交付要求。

之前的音频导入网页 Demo 是前期软件验证，不等于最终参赛作品已经实现手机应用与设备协同。官方 SDK 尚未取得，具体兼容性留待核实。

## 2. 平台选择留待应用接入

按用户后续决定，当前不限定安卓或 iPhone，先设计手机竖屏与不同屏幕尺寸的界面。应用安装、录音豆连接和系统通知的兼容性，在设备与 SDK 可用后核实。

这一选择影响应用工程的搭建，不影响下面的页面内容。暂不安装框架或承诺某种技术一定兼容官方 SDK。

## 3. 第一屏只解决一件事

用户看懂一项从课堂原话中提取的作业，修改错误并确认保存。

建议布局（示例内容，不是模型实际提取结果）：

```text
返回                          核对任务

请核对老师的要求
确认后加入你的任务

作业名称
完成课程报告                  修改

截止日期
10 月 10 日                   修改

原话依据
“课程报告请在十月十日提交。”

需要确认的信息
没有明确截止时间时，在这里提示

                 确认保存
```

- 手机竖屏、单列、大按钮；滚动与键盘弹出时仍能完成编辑。
- 使用中文，保持已确认的任务、截止时间、原话、建议等词汇一致。
- 原话保持只读，用户修改的是任务内容；修改后不丢失原话依据。
- 截止时间不明确时保留空值，不默默填入默认期限。
- 有可用录音和时间片段后再加入回听功能，不能做一个看似能回听但无音频的按钮。
- 初期若使用示例数据，页面明确标注；本地演示保存不能声称已写入 B 的后端。

## 4. A 与 B 的交接

| 负责人 | 第一次交付 |
| --- | --- |
| A | 展示一项任务、编辑名称和截止日期、发出确认保存请求、显示结果 |
| B | 返回真实任务草稿与原话；接收核对结果；保存后可重新读取 |
| 两人 | 统一任务标识、名称、截止时间、原话、待确认项和保存结果的格式 |

如果 B 的接口未完成，先用同一份格式制作标注清楚的页面样例。接口数据结构应独立于页面样式，选安卓或 iPhone都不要求 B 重写任务提取逻辑。

## 5. 第一屏的验收

- [ ] 能展示从 B 返回的一项任务和原话依据。
- [ ] 能修改任务名称与截止日期；原话不被改写。
- [ ] 点击确认时显示保存中，避免重复点击。
- [ ] 成功结果来自实际保存返回；失败时保留编辑内容并可重试。
- [ ] 重新打开或重新读取后，仍能看到已保存的修改。
- [ ] 在选定手机的真实屏幕上能完成操作，键盘和底部区域不遮挡关键按钮。
