# 录音便签首页与详情：交互设计

更新：2026-09-25。用户已确认纸张便签版本，并要求按定稿实现交互。`mobile-preview/` 已实现本地前端 Demo；早期蓝色卡片、液态玻璃方向不再作为本页标准。

## 已确认的视觉

- 中文标题、白色纸张、手绘感细边框；大标题沿用定稿字形。
- 原创括号猫直接使用用户提供图，不重画眼睛、花纹或动作。待确认页使用原创问号狗。
- 右侧三页签：内容黄色、待确认绿色、注意红色。选中页签与纸张为连续轮廓；边缘颜色向纸内渐淡。
- 不加品牌标签或锚学社中文标志。底部为录音／日程／我的。
- 新录音整理完成时采用页面中央弹窗，左上沿探头猫、右上关闭、底部查看任务。关闭不删除便签。

## 核心结构与交互

一段录音对应一张便签，一张便签可有多项任务；当前 Demo 用一段录音、一项课程报告验证链路。

1. 我的录音：录音卡片进入详情；「＋」仅用于体验示例提醒。
2. 内容：任务、材料、截止时间、建议顺序；原话入口与核对加入日程按钮。
3. 待确认：日期、是否尚无明确日期、PDF／Word／稍后确认；保存只保存核对结果，不自动加入日程。
4. 注意：重要要求、核对状态、AI 建议与老师要求的区别，可标记已读。
5. 加入日程：未核对完成时引导补充；集中确认弹窗通过后保存，取消不保存；重复操作指向同一任务。
6. 修改：便签核对结果与已保存日程分开；新结果再次确认后才更新旧日程。
7. 日程：展示已确认任务、截止日期与示例建议顺序，可标记完成。

原话保持只读；没有实际附件、音频时明确说明。原话未说明日期／时间，不编造具体值或 23:59。无需用户填写空闲时间或工作量。建议开始日期、复杂度估计及可调整计划属于后续真实分析和计划模块。

## 数据与设备边界

本轮使用示例原话，本地存储保存确认结果；未连接后端和录音豆。提醒由按钮演示，不冒充真实设备事件。真实流程仍是：发现录音 → 同步 → 转写与整理 → 摘要就绪 → 弹窗 → 便签，后续必须补失败状态。

后续由 B 提供录音、原话、任务、待确认项及变更数据，A 替换示例与本地保存接口。语气／话外音分析是后续能力，不在当前侧边页签中冒充可用功能。设备自动发现、后台同步、系统通知、安装包及真机适配仍待 SDK 和测试。
