## 直接拼接的阻塞点

### 1. 页面没有加载或调用数据模块

`mobile-preview/index.html:8` 只加载 `model.js` 与 `app.js`。`app.js` 使用 `NoteModel`，没有调用 `AnchorReviewData` 或 `AnchorReviewAPI`。

整合时加载顺序应为数据模块、接口模块、页面逻辑，并将分析结果传入页面。仅增加 script 标签仍然不算完成。

### 2. 示例内容与动态多任务的结构不同

`mobile-preview/index.html:40` 等位置写死课程报告、第三章、示例日期、原话和建议。`model.js:6` 只有一个 review，`model.js:24` 的任务编号固定为 `course-report`。页面没有任务名称、要求的编辑入口。

整合需按 tasks 数组逐项渲染，分别保留编号、名称、截止日期、原话和 AI 建议，并提供名称与要求修改。录音标题与时间也应来自实际数据；没有时长时不沿用“12分钟”。保留猫狗和纸张设计，不把固定示例内容当成真实结果。

### 3. 待确认规则不通用

`index.html:50-51` 固定问日期和 PDF/Word。`model.js:23` 强制要求提交格式；实际分析结果可能没有格式问题，也可能需要确认组别或任务归属。另一边的 `prepareConfirmation` 会阻止仍有 clarifications 的任务批次保存。

整合需依据 questions 动态显示问题，补充后重新分析；不能仅选择一个文件格式就认为任意归属问题已解决。没有明确日期的任务允许 null，不要强填截止日期。当前模块没有问题与单项任务的关联信息，暂采用整批有疑问则不确认保存的保守规则，详见 integration/README.md。

### 4. 本地示例日程与正式任务保存不是同一操作

UI 的 save 调用 localStorage，接口模块的 confirm 需要 B 提供真实保存接口；后者默认关闭。现有日程页面主要是固定步骤清单，不是按日期自动生成的真实建议日程。

接通前必须保留示例标记。正式模式只有收到并校验后端成功响应后才能显示“已保存”；该响应不代表已经排程或设置通知。旧示例存储不得冒充后端记录。保存失败时保留编辑内容；超时结果未知时复用请求编号查询或重试。

### 5. B 后端仍需单独联调

此轮只检查本地文件，未重新检查 B 的远程仓库。依据前次 `e783bbf` 的检查结果，B 有转写和分析，保存、读取接口尚缺；如 B 后续已更新，应先重新核实。

B 当时的服务只提供根页面与 API，没有提供本项目的 JS/CSS/图片目录。双方都使用过 8765 端口；不能同时占用，也不能只复制 HTML 后就宣称完成。需要统一静态资源服务或同源开发代理。不要直接移除 B 的来源校验来绕过连接问题。
